## 5. 機制：`tp_quantity` 的不對稱會吃掉任何人工建立的對沖

`grid_engine/decision.py:97`
```python
def tp_quantity(base_qty, my_position, opposite_position, position_limit, position_threshold):
    if my_position > position_limit or opposite_position >= position_threshold:
        return base_qty * 2
```
生產：`position_limit = initial_quantity × limit_multiplier = 0.02 × 5 = 0.1`。
多 0.60 與空 0.20 **都** > 0.1 ⇒ 兩側止盈量都是 0.04，進場量都是 0.02。

一次完整往返（一下穿 + 一上穿）的淨效果：
- 多頭：+0.02 − 0.04 = **−0.02**
- 空頭：−0.04 + 0.02 = **−0.02**

⇒ 持倉 > 0.1 之後，這台機器在**等量縮減毛部位（de-gross）**，不是在賺網格價差。
空頭基數 0.20 vs 多頭 0.60 ⇒ **同樣的 -0.02 對對沖的相對傷害是 3 倍**。

**投影（機制推論，非實測）**：空頭被壓向 `position_limit`≈0.1 附近（跌到 0.1 以下時
`my_position > position_limit` 轉 false、止盈量回 0.02，恢復對稱 ⇒ 平衡點約 0.1，不是 0）。
delta 將由 +0.40 走向 **~+0.50**。同族現象已有前例：舊回測記錄的「持倉被壓在 0.28 平衡點」
就是同一個 `position_limit` 效應。

**這條直接否決 TODO 2**：入金 ~25 補到 0.58/0.58 之後，網格會再把空頭拆回 ~0.1。
要讓「補中性後長期持有」成立，必須先讓對沖側免疫於這個不對稱（例如止盈量加倍只對
「淨曝險方向」那側生效，或對沖倉走獨立帳本不進網格）——**這是新的設計問題，不在任何現有 TODO 裡**。

## 8. 附帶結論：mult=40 在現行資本下是惰性參數（不必重跑回測就能證明）

`#14` 的複核疑慮是「回測用 20x 算保證金、實盤是 5x，低估需求 4 倍」。用實測數字直接算：

| | 值 |
|---|---|
| 每層 0.02 的保證金 @5x @570.66 | **2.283** |
| 可用餘額 | 17.955 |
| 可再加層數 | **7 層**（17.955 / 2.283 = 7.87） |
| 加滿 7 層後多頭 | 0.60 + 0.14 = **0.74** |
| 裝死門檻（mult=40） | **0.80** |
| 到 0.80 需要 | 10 層 = 保證金 22.83（**缺 4.87**） |

⇒ **多頭在 5x 下到不了 0.8 的裝死門檻**：保證金會先耗盡，實際的補倉煞車是**交易所拒單
（-2019）**，不是策略的裝死邏輯。（且價格下跌時 uPnL 惡化會讓可用餘額比上表更快歸零，
所以 7 層是上界。）空頭 0.20 距 0.8 需 30 層，更不可能。

**這對 #14 的意義（雙面）**：
- 好消息：mult=40「關掉裝死」的尾部風險，在現行資本下被保證金天花板實質封住 ⇒
  「用 20x 算保證金而低估 4 倍」這個疑慮**不會讓 mult=40 變成災難**，因為真正的限制器不是它。
- 壞消息：**煞車從策略層掉到交易所層**。mult=20（thr=0.4）下多頭 0.60 > 0.4 會立刻裝死
  （= 07-10 那次 104h 凍結），mult=40 把它解除後，現在唯一的補倉上限是「錢用完被拒單」。
  這不是設計，是副作用。回測完全沒建模 -2019 拒單通道（requote 實驗的 6 月 cap 10x→15x
  正是為了補這個未建模項）。

⇒ **#14 的正式複核（用 5x 重跑分段掃描）仍該做，但優先度可以降**：結論不會是「mult=40 危險」，
而會是「mult 在現行資本下無效，該管的是保證金預算」。真正該補的是**保證金耗盡路徑的建模**，
不是重跑 mult 掃描。
